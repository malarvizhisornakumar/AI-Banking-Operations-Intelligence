# Business Rules

# AI Cheque Extraction Quality Analytics Platform

## Overview

This document defines the business validation rules used during cheque data extraction, quality validation, and reporting.

The Vision Language Model (VLM) extracts cheque information from scanned cheque images. These rules ensure the extracted data is accurate, complete, and suitable for business reporting.

---

# Business Rule BR001

## Rule Name

Leading Zero Preservation

### Description

Account Number and Cheque Number must preserve all leading zeros exactly as printed on the cheque.

### Valid Example

Account Number

0001234567

Cheque Number

000123

### Invalid Example

Account Number

1234567

Cheque Number

123

### Business Impact

Removing leading zeros changes the original cheque information and may result in incorrect customer identification or cheque validation.

---

# Business Rule BR002

## Rule Name

Account Number Length Validation

### Description

The extracted Account Number must match one of the approved banking account formats.

| Account Type | Expected Length |
|---------------|----------------|
| Customer Account | 10 Digits |
| Corporate Account | 6–8 Digits |
| Manager Cheque | 16 Digits |

### Validation

If the extracted account number does not match any valid length,

Validation Status = Failed

Manual Review = Required

---

# Business Rule BR003

## Rule Name

Mandatory Field Validation

### Description

The following fields are mandatory and cannot be NULL or blank.

- Account Number
- Account Name
- Cheque Number
- Cheque Date

### Validation

If any mandatory field is missing,

Validation Status = Failed

---

# Business Rule BR004

## Rule Name

Duplicate Cheque Validation

### Description

The combination of

Account Number + Cheque Number

must always be unique.

### Valid Example

| Account Number | Cheque Number |
|----------------|---------------|
|0001234567|000123|
|0009876543|000123|

Valid because Account Numbers are different.

### Invalid Example

| Account Number | Cheque Number |
|----------------|---------------|
|0001234567|000123|
|0001234567|000123|

Duplicate cheque detected.

### Validation

Duplicate records are flagged for manual investigation.

---

# Business Rule BR005

## Rule Name

Cheque Date Validation

### Description

All Citi Bank cheque dates must fall within the project's historical business period.

### Allowed Date Range

01-Jan-2000

to

31-Dec-2017

### Validation

Dates outside the valid range are flagged for manual verification.

### Notes

Dates are handwritten on most cheques.

The extracted date may appear in different formats.

Examples

01/02/2005

1-2-05

01-Feb-2005

All valid dates should be normalized into a standard reporting format.

---

# Business Rule BR006

## Rule Name

Image-to-Cheque Validation

### Description

Each scanned image represents exactly one cheque.

### Validation

1 Image

=

1 Cheque

Images containing multiple cheques or invalid scans must be flagged for review.

---

# Business Rule BR007

## Rule Name

Low Confidence Validation

### Description

Every extracted record contains a confidence score generated by the Vision Language Model.

### Validation

If Confidence Score is below the configured threshold,

Validation Status = Manual Review Required

### Purpose

Low-confidence handwritten fields should be reviewed before final reporting.

---

# Business Rule BR008

## Rule Name

Manual Correction Workflow

### Description

If AI extraction fails or produces low-quality output, the record enters manual validation.

### Workflow

AI Extraction

↓

Validation Failed

↓

Manual OCR

or

Manual Data Entry

↓

Quality Validation

↓

SQL Server Update

↓

Reporting

### Notes

Failed records are corrected whenever possible.

They are not permanently rejected.

---

# Business Rule BR009

## Rule Name

Folder Hierarchy Validation

### Description

Every cheque image must belong to a valid folder hierarchy.

Box Barcode

↓

RC Box Barcode

↓

Shoe Box Barcode

↓

Cheque Image

### Validation

Every extracted cheque must have

- Box Barcode
- RC Box Barcode
- Shoe Box Barcode

Missing hierarchy information results in validation failure.

---

# Business Rule BR010

## Rule Name

Batch Image Count Validation

### Description

Each Shoe Box should contain approximately 2,000–3,000 cheque images.

### Validation

The total scanned image count recorded for a Shoe Box should match the number of extracted records.

If

Scanned Images

≠

Extracted Records

the batch is flagged for reconciliation.

---

# Summary

The validation process ensures:

- Data completeness
- Business rule compliance
- Duplicate prevention
- Historical date validation
- Account number integrity
- Folder hierarchy consistency
- AI extraction quality
- Manual correction workflow
- Reliable business reporting

These rules form the foundation of the AI Cheque Extraction Quality Analytics Platform.
